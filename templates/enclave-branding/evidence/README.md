# Evidence for the branding geometry

Everything in `../README.md` is measured, not assumed. This is the measurement.

## `logo-circular-crop.png`

A **full-bleed square** test image injected into the logo container of the **live enclave**
(`https://ork5.tideprotocol.com/`, `main .logo .img_container`) and screenshotted at device scale.

The test image is 838×838 (Tide's own logo dimensions) and contains:

- a solid blue fill covering the whole canvas
- a **red triangle in each corner**
- a **yellow circle** inscribed in the canvas — the predicted survival boundary
- a **black square** inset 14.65% per side — the largest square that should survive

In the screenshot **all four red corners are gone**. The yellow circle sits exactly at the crop
edge, and the black square is comfortably inside it.

That is the whole rule in one picture: the corners of your canvas are not displayed.

## How it was measured

```js
getComputedStyle(document.querySelector('main .logo .img_container'))
// width/height 153px, border-radius 50%, background-size cover,
// background-position 50% 50%, background-color rgb(255,255,255)
```

Confirmed by hit-testing, so it is not just a declared style that something else overrides:

```js
const r = el.getBoundingClientRect();
document.elementFromPoint(r.left + 2, r.top + 2) === el   // false — the corner is not the logo
document.elementFromPoint(r.left + r.width/2, r.top + r.height/2) === el  // true — the centre is
```

Source rule, from `https://ork5.tideprotocol.com/app.<hash>.css`:

```css
main .logo .img_container {
  width: 85%; height: 85%;
  background-color: var(--white);
  border-radius: 50%;
  background-size: cover;
  background-position: center;
  background-repeat: no-repeat;
}
main .logo {                        /* wrapper */
  width: max(32vw, 100px); height: max(32vw, 100px);
  max-width: 140px; max-height: 140px;
}
@media (min-width: 1024px) { main .logo { max-width: 180px; max-height: 180px; } }
```

So the rendered logo box is **85px to 153px**, and 153 × 3 (DPR) = 459 device px is why 512 is the
practical floor for a source image.

## Tide's own defaults, measured

Fetched from the same host:

| File | Dimensions | Format |
|---|---|---|
| `assets/default-logo.png` | 838×838 | PNG, 8-bit RGBA |
| `assets/default-background.jpg` | 3840×2160 | JPEG |

The default logo's artwork is a **wide wordmark**, 703×366 of opaque content on the 838×838 canvas,
whose furthest opaque pixel sits at **0.942×** the crop radius — it is deliberately sized to survive
the circle, with little to spare.

## Upload limits

From `BrandingTab.tsx` in the admin UI: **PNG, JPEG, GIF or WebP, up to 5 MB, SVG not allowed**, and
**no dimension validation of any kind**. Nothing rejects a badly shaped logo — it just ships clipped.

## `logo-kinds.png`

The nine `--kind` marks, each composited onto a white circle and clipped to a circle — exactly what
the enclave does. Generated by `make-branding.py` with no image model and no third-party libraries.

Rendered at 256px for the sheet; the real default is 1024×1024.
